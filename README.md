## Autonomous Car Simulation (MetaDrive) — Sensor Fusion + BC → PPO

One-page summary: open `poster.html` in a browser.
Start: `.\run.ps1`

**Phase 1**: Behavioral Cloning (IDM expert demonstrations)  
**Phase 2**: PPO fine-tuning (Stable-Baselines3) warm-started from Phase 1

### What this repo contains

- **A sensor-fusion policy** (`models/fusion_model.py`) that predicts \([steering, acceleration]\) from:
  - **RGB camera** frames (128×128) via EfficientNet-B0
  - **19-dim numeric state** via a small MLP
- **A full pipeline**: collect → preprocess → train → evaluate → explain (Grad-CAM) → export (ONNX) → fine-tune with PPO
- **Generated artifacts** already in-repo: plots in `report/`, Grad-CAM visuals in `gradcam_outputs/`

## Analysis summaries

### Phase 1 (Behavioral Cloning) — what worked vs what failed

Source: `report/failure_analysis.md` (generated by `failure_report_md.py`).

- **Training behavior**:
  - Fast convergence to **0.00043 MSE** (best around epoch ~20), with **no obvious overfitting** (train/val track closely).
  - Unfreezing the EfficientNet backbone after the first epochs creates a noticeable improvement in validation loss.
- **Runtime evaluation (20 unseen episodes)**:
  - **0% success** (destination not reached), **95% out-of-road**, **5% crash**.
  - Avg episode: **~299 steps**, **~98 m** traveled, avg velocity **~3.0 m/s** under the hybrid controller.
- **Primary root cause**:
  - **Moderate turn underestimation** (\(|steer| \approx 0.1\)–\(0.4\)) → the vehicle drifts wide on curves until it goes out-of-road.
  - Extreme turns (\(|steer| > 0.5\)) are predicted accurately, so the issue is concentrated in the “small-to-medium correction” regime.
- **Secondary contributors**:
  - **Speed distribution mismatch**: IDM data is collected at higher cruise speed than the runtime PID ramp-up target, so early timesteps look out-of-distribution.
  - **Covariate shift**: pure BC has compounding error; without recovery demonstrations, small drift becomes unrecoverable.

### Grad-CAM — evidence for the failure mechanism

Source: `gradcam_outputs/findings.md` (generated by `visualize_attention.py`).

- **What works**:
  - Hard turns get good attention and good steering accuracy.
  - Acceleration attention tends to focus on road surface ahead.
- **What fails**:
  - On moderate turns, attention often shifts to **sky/terrain** instead of **road edges**, matching the consistent “insufficient steering → out-of-road” failures.

### Phase 2 (PPO fine-tuning) — what improved and what stayed hard

Source: `report/rl_summary.txt` + `report/rl_analysis.png` (generated by `rl_report.py`).

- **Warm start**:
  - PPO is initialized from **Phase 1 SensorMLP weights**, which stabilizes early learning versus training from scratch.
- **Big wins**:
  - **Survival time improved ~7.5×** vs BC baseline (avg episode length **299 → 2256** steps at best).
  - **Crash rate returns to 0%** after a short 5–10% spike around steps 280k–310k. The final checkpoint is crash-free.
- **Main limitation**:
  - **Reward sparsity**: destination reward is rarely/never reached within 500k steps, so “success rate” stays at **0%** even while safety improves.
- **Most promising next steps**:
  - Curriculum learning + denser navigation/progress reward, and improving BC steering (weighted loss / better camera) to give PPO a stronger starting policy.

## Architecture

```text
Camera frame (128x128x3)                 Sensor state (19,)
        |                                       |
 EfficientNet-B0 backbone               MLP: 19 → 64 → 128 → 128
 (ImageNet pretrained)                  LayerNorm + ReLU
        |                                       |
     FC 1280 → 512                          128-dim vector
        |                                       |
        └────────────── Concatenate (640) ──────┘
                           |
                       FC 640 → 256
                       FC 256 → 128
                       FC 128 → 2
                           |
            [steering ∈ (-1,1), accel ∈ (-1,1)]
```

## Setup (Windows / PowerShell)

The environment for this folder is `car_env`. It is already created. Use that interpreter, not the system Python: the system `torch` and `torchvision` builds do not match, so imports fail there.

```powershell
.\car_env\Scripts\python.exe inference.py
```

That loads `checkpoints_v2/best_model.pth` and runs a dummy-frame benchmark. A real saved frame from `data_clean/processed/episode_0000` predicts steering near 0 and acceleration near 1, matching that frame's label. The ONNX file loads as well, and `rl_checkpoints/ppo_av_final.zip` loads in Stable-Baselines3.

MetaDrive's asset pack is installed inside `car_env`. A headless run with the camera on completed 15 steps. `env_test.py` opens a window (`use_render=True`); close that window when you are done.

`models/visual_branch.py` had been overwritten by an older copy of the PPO training script, so `FusionModel` could not import `VisualBranch`. It is restored to the EfficientNet-B0 branch that matches `best_model.pth`. The overwritten script is kept outside this repo. Do not retrain, and do not delete `checkpoints_v2`, `rl_checkpoints`, `data_clean`, or `data_idm_auto`. Those folders are gitignored, so they are not on GitHub.

Recreate `car_env` only if that folder is missing. The one already here uses the CPU build of PyTorch, which is what the checks above ran on. `requirements.txt` pins that set.

```powershell
python -m venv car_env
.\car_env\Scripts\Activate.ps1

python -m pip install --upgrade pip

# Core sim + ML stack
pip install metadrive-simulator==0.4.2.3
pip install numpy pandas matplotlib opencv-python

# PyTorch (pick one)
# CUDA (example: cu121)
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
# or CPU-only:
# pip install torch torchvision

# RL + ONNX + UI
pip install stable-baselines3==2.3.2 gymnasium==0.28.1
pip install onnx onnxruntime
pip install streamlit plotly
```

## Run the full pipeline

### 1) Collect IDM expert demonstrations

```powershell
python run_collector.py
```

This runs `collect_idm_auto.py` repeatedly until ~90k steps are collected.

### 2) Preprocess + augment

```powershell
python preprocess.py
```

Outputs `data_clean/processed/episode_*/{actions.csv,sensors.csv,frames/*.npy}`.

### 3) Train/val split (episode boundary)

```powershell
python split.py
```

Creates `data_clean/split.json`.

### 4) Train (Behavioral Cloning)

```powershell
python train.py
```

Saves `checkpoints_v2/best_model.pth` and `checkpoints_v2/history.json`.

### 5) Evaluate + generate reports

```powershell
python evaluate.py                 # writes checkpoints_v2/eval_metrics.json
python visualize_attention.py      # writes gradcam_outputs/*.png and gradcam_grid.png
python failure_report_md.py        # rebuilds report/* from saved history and eval JSON
```

### 6) Export to ONNX

```powershell
python export_onnx.py
```

### 7) Run the agent in MetaDrive

```powershell
python run_agent.py
```

This uses the BC model for **steering** and a PID controller for **speed** (default target ~5 m/s in `evaluate.py` / `run_agent.py` style logic).

### 8) Phase 2 — PPO fine-tuning

```powershell
python rl_train.py
python rl_report.py                 # rebuilds report/rl_analysis.png and rl_summary.txt from rl_logs/rl_log.json
```

### 9) (Optional) Streamlit dashboard

```powershell
streamlit run dashboard.py
```

## Notes & next steps

- **Primary BC failure mode**: moderate turn underestimation (\(|steer| \in [0.1, 0.4]\)) → out-of-road.
- **Why Grad-CAM matters here**: attention drifts to sky/terrain on moderate turns, consistent with the runtime failure mechanism.
- **Most promising fixes**:
  - Turn-weighted loss (3–5× on moderate turns)
  - Top-down / better road-geometry camera
  - DAgger-style recovery demonstrations near boundaries
  - Denser navigation reward / curriculum for PPO (current destination bonus is too sparse)
